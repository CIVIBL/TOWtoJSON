# D1: Structured conversion report module

**Avoid:** Don't compute the report inside generate.js or the UI — it must be a pure module (`src/js/report.js`) so tests can assert on it and both output formats (OWB now, NR in Phase E) reuse it.

## Steps

### Step 1: Write failing tests (test/report.test.js)

Feed a modified Skaven fixture containing (a) one misspelled unit (`232 - 31 Clanrets` → unmatchable... note: fuzzy matching may still catch this; use `232 - 31 Zzzzz` for a guaranteed miss) and (b) one unknown token (`Grey Seer, Made Up Thing`). Assert:

- `report.matched === 9`, `report.total === 10`
- `report.dropped` contains `{ name: 'Zzzzz', points: 232 }`
- `report.unknownTokens` contains `{ unit: 'Grey Seer', tokens: ['Made Up Thing'] }`
- `report.points.parsed === 2197`, `report.points.header === null`, `report.points.computed` is a number; per-unit entries where `computed !== anchor points` appear in `report.points.unitMismatches`
- Unplaced magic items from B3 surface in `report.warnings`

### Step 2: Implement src/js/report.js

```js
export function buildReport(parsed, owbJson) // parsed = parseWithFactionData output (+ headerPoints)
```

`computed` per unit: `unit.points (template base) + sum(active equipment/armor/options/command points, honoring perModel * strength) + selected magic item points`. Exact per-model semantics: copy how OWB displays unit cost — check `points` handling in reference-files/tree-army_owb.json entries and mirror it. Mismatch tolerance 0 (exact); this check is advisory (warning), not blocking, because template points can legitimately differ from a stale BCP export.

### Step 3: Green, commit

`node --test test/report.test.js && npm test`. Commit: `feat: structured conversion report`
